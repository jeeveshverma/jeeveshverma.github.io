01Why build it

A URL shortener is a small domain, which is the point. With the business logic out of the way, the interesting parts of a backend service are what's left: clean layering, concurrency safety, observability, a graceful lifecycle, and tests.

I wanted a service I could put under the same pressure I put other people's services under at work, and know exactly why every test exists.

02Architecture

Requests go through a middleware chain, then the router, then a domain service that talks only to a Store interface. A Redis or Postgres store could replace the in-memory one without touching the handlers.

client→recover · request-id · metrics · rate-limit→ServeMux→shortener.Service→Store→MemoryStore + reaper + snapshot
  • Full REST surface: create (with vanity codes and dedupe-by-URL), redirect, stats, delete, paginated list and global stats.
  • Durable without a database: atomic JSON snapshots, written to a temp file and renamed into place, so a crash mid-write can't corrupt them.
  • Expiry enforced twice: on read, and by a background reaper that reclaims expired links.
  • Observability: structured log/slog lines with a request ID, and a hand-rolled Prometheus /metrics endpoint. The route label uses the matched pattern, not the raw path, to keep cardinality bounded.

03Unguessable codes

Sequential IDs are shorter but enumerable: anyone can walk the URL space and estimate your volume. linkforge draws random base62 codes from a CSPRNG and uses rejection sampling, so no character is more likely than another.

internal/shortener/codegen.go
// Largest multiple of len(alphabet) that fits in a byte; values at or above
// it are rejected to keep the distribution uniform.
const maxUnbiased = 256 - (256 % len(alphabet))

for len(out) < n {
    if _, err := rand.Read(buf); err != nil {
        return "", fmt.Errorf("read randomness: %w", err)
    }
    for _, b := range buf {
        if int(b) >= maxUnbiased {
            continue
        }
        out = append(out, alphabet[int(b)%len(alphabet)])
        if len(out) == n {
            break
        }
    }
}

Generator is an interface, so tests inject a stub that returns the same code twice and prove the service retries on collision.

04Rate limiting

Each client gets a token bucket. Buckets refill lazily from elapsed time, so there's no timer per client, and idle buckets are garbage-collected, so memory tracks active clients rather than every client ever seen.

internal/ratelimit/limiter.go
elapsed := now.Sub(b.last).Seconds()
b.tokens = min(l.burst, b.tokens+elapsed*l.rps)
b.last = now
if b.tokens < 1 {
    return false
}
b.tokens--
return true

The clock is injected (l.now()), which is what makes this testable without sleeping.

05Test strategy

The rule I hold myself to: no test sleeps, and no test depends on luck.

  1. Deterministic clocks drive expiry, reaping and token refill, so time-based paths run instantly and identically every time.
  2. A stub code generator forces collisions on demand to exercise the retry path.
  3. The race detector runs on the whole suite, including a 5,000-goroutine contention test on the store.
  4. Native Go fuzzing hits URL normalisation and vanity-code validation; a short fuzz run also executes in CI.
internal/shortener/fuzz_test.go
func FuzzValidateCustomCode(f *testing.F) {
    for _, s := range []string{"", "ab", "abc", "my-vanity_1", "bad char", "emoji😀"} {
        f.Add(s)
    }
    f.Fuzz(func(t *testing.T, code string) {
        if err := validateCustomCode(code); err != nil {
            return
        }
        if len(code) < minCodeLength || len(code) > maxCodeLength {
            t.Fatalf("accepted code %q outside length bounds", code)
        }
        // ...every accepted rune must be in the allowed alphabet
    })
}
The testing idea

A fuzz test doesn't check an expected output. It checks a property: if the validator accepts something, that something must be safe. Rejecting is always allowed.

07CI gates

Every push runs, in order: gofmt, go vet, the race-enabled test suite, a coverage gate that fails the build below 85% on the internal/ packages, and golangci-lint.

.github/workflows/ci.yml
- name: Coverage gate (>= 85% over internal packages)
  run: |
    go test -covermode=atomic -coverprofile=coverage.out ./internal/...
    total=$(go tool cover -func=coverage.out | awk '/^total:/ {print $3}' | tr -d '%')
    awk "BEGIN {exit !(${total} >= 85)}" || { echo "::error::coverage ${total}% is below the 85% threshold"; exit 1; }
