01Why build it

The job model is simple on purpose. The interesting part is the concurrency: a delay-aware queue that blocks a worker exactly until the next job is due, correct wake-ups across many workers, and a graceful shutdown that lets in-flight jobs finish instead of killing them mid-run.

Retries, backoff and dead letters are where background systems quietly lose work. I wanted a codebase where each of those paths has a test that proves it.

02How a job moves

Producers push into a queue. Workers pop, run the handler through a middleware chain, and route the result.

Enqueue / EnqueueIn→MemQueue (min-heap)→worker N→middleware→handler + timeout + recover
  • Success: counted, and the OnSuccess hook fires.
  • Error with attempts left: re-queued with NotBefore = now + backoff(attempt).
  • Error with attempts exhausted, a panic, or no handler: routed to the dead-letter queue with the last error kept.

The pool depends only on a Queue interface. Scheduling lives in the queue, not the pool, so one mechanism handles both delayed jobs and backoff retries, and a Redis or broker-backed queue could drop in unchanged.

03A queue that sleeps precisely

Jobs sit in a min-heap ordered by due time, then priority. Pop either returns a due job or waits on a timer for the earliest one, waking early if a new push, a cancellation or a close arrives first.

memqueue.go
if len(q.items) > 0 {
    if d := q.items[0].NotBefore.Sub(q.now()); d <= 0 {
        job := heap.Pop(&q.items).(Job)
        // If the next job is also ready, wake a sibling worker so a
        // single push/timer can drain a backlog across the pool.
        if len(q.items) > 0 && !q.items[0].NotBefore.After(q.now()) {
            q.signal()
        }
        q.mu.Unlock()
        return job, nil
    } else {
        wait = d
    }
}
// ...
select {
case <-ctx.Done():
    stopTimer(timer)
    return Job{}, ctx.Err()
case <-q.closedCh:
    stopTimer(timer)
    return Job{}, ErrClosed
case <-q.notify:
    stopTimer(timer)
case <-timerC:
}

Due time always beats priority, so a scheduled job never jumps the queue. Higher priority only wins among jobs that are due at the same time.

04Backoff with jitter

The delay is Base × Factor^(attempt-1), capped at Max, then perturbed by ±Jitter. The default is 100ms, doubling, capped at 30s, with 20% jitter. Jitter spreads out jobs that failed together so they don't all retry in lockstep.

backoff.go
d := float64(b.Base) * math.Pow(b.Factor, float64(attempt-1))
if max := float64(b.Max); b.Max > 0 && d > max {
    d = max
}
if b.Jitter > 0 {
    rnd := b.Rand
    if rnd == nil {
        rnd = rand.Float64
    }
    // Perturb by ±Jitter: delta ∈ [-Jitter, +Jitter].
    delta := (rnd()*2 - 1) * b.Jitter
    d *= 1 + delta
}

Rand is a seam for tests: inject a function that returns a fixed value and the "random" delay becomes exact.

05Failure handling

Every handler runs with panic recovery and an optional per-job timeout. It runs on a background context, so Shutdown stops workers from pulling new jobs but lets the ones in flight finish, up to the caller's deadline.

pool.go
func (p *Pool) runHandler(h HandlerFunc, job Job) (err error) {
    ctx := context.Background()
    if p.jobTimeout > 0 {
        var cancel context.CancelFunc
        ctx, cancel = context.WithTimeout(ctx, p.jobTimeout)
        defer cancel()
    }
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("handler panicked: %v", r)
        }
    }()
    return h(ctx, job)
}

If re-queueing a retry fails, the job goes to the dead-letter queue rather than vanishing. A bad handler can't take a worker down, and a lost job always leaves a trace.

06Test strategy

The whole suite runs under -race. It covers:

  1. Queue semantics: FIFO, ordering by due time, priority ordering, due time beating priority.
  2. Blocking behaviour: Pop blocks until a push, returns on cancellation, and unblocks when the queue closes.
  3. Contention: a concurrent producers-and-consumers stress test.
  4. Pool lifecycle: retry then success, dead-letter after exhaustion, unknown kinds, panic recovery, graceful drain, middleware, stats and typed handlers.
  5. Fuzzing: backoff maths and the typed-payload decoder.
fuzz_test.go
b := Backoff{
    Base:   time.Duration(baseMs) * time.Millisecond,
    Max:    time.Duration(maxMs) * time.Millisecond,
    Factor: 2,
    Jitter: jitter,
    Rand:   func() float64 { return 1 }, // maximum positive jitter
}
d := b.Delay(attempt)
if d < 0 {
    t.Fatalf("negative delay %v for attempt=%d ...", d, attempt)
}
upper := time.Duration(float64(b.Max)*(1+jitter)) + time.Millisecond
if d > upper {
    t.Fatalf("delay %v exceeds cap+jitter %v", d, upper)
}
The testing idea

Pin the random source to its worst case. With Rand forced to 1, jitter is at its maximum, so the fuzzer checks the bound that actually matters: the delay is never negative and never exceeds the cap plus jitter, whatever the attempt number.

07CI gates

Every push runs gofmt, go vet, the race-enabled suite, a coverage gate that fails below 85%, golangci-lint, a Docker build, and a 20-second fuzz smoke run for each fuzz target.

.github/workflows/ci.yml
fuzz:
  name: Fuzz (smoke)
  steps:
    # ...
