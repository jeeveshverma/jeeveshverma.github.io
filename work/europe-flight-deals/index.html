Sub-₹20,000 return fares from India to Europe do exist, and they vanish within hours. This automation checks every morning so I don't have to: it scans round trips from 7 Indian airports to 22 European ones through the Amadeus API and ranks anything under the threshold.

01What it does

  1. Reads Amadeus credentials and search settings from application.properties.
  2. Searches round-trip fares from DEL, BOM, BLR, MAA, HYD, CCU and AMD.
  3. Checks 22 European destinations, from London and Paris to Budapest, Warsaw and Istanbul.
  4. Converts every price to INR and keeps the deals under the threshold.
  5. Prints them ranked by price, each with a Google Flights link.
sample output
Found 2 deal(s) under ₹20,000:

 1. ₹18,450 | DEL → BUD (Budapest) | 2026-08-24 → 2026-09-07 | W6 | 1 stop(s)

The threshold, how far ahead to search, the trip length and both airport lists are all configurable.

02The scan loop

One search per origin and destination pair, 250ms apart to stay inside the API's rate limit. A failed search is logged and skipped, so one bad route can't sink the whole run.

AmadeusFlightService.java
for (String origin : config.originAirports()) {
    for (Airport destination : europeDestinations) {
        try {
            Optional<FlightDeal> cheapest =
                    searchCheapestRoundTrip(origin, destination, departure, returnDate);
            cheapest.ifPresent(deal -> {
                if (deal.priceInr() <= config.maxPriceInr()) {
                    allDeals.add(deal);
                    log.info("DEAL FOUND: {}", deal);
                }
                // ...
            });
            Thread.sleep(250);
        } catch (Exception e) {
            log.warn("Search failed for {} → {}: {}", origin, destination.iataCode(), e.getMessage());
        }
    }
}
allDeals.sort(Comparator.comparingDouble(FlightDeal::priceInr));

03Tokens and 401s

Amadeus uses OAuth client credentials. The service caches the access token with its expiry and fetches a new one only when needed. If a search comes back 401 anyway, it drops the token, re-authenticates once and retries the same request.

AmadeusFlightService.java
HttpResponse<String> response = httpClient.send(request, HttpResponse.BodyHandlers.ofString());
if (response.statusCode() == 401) {
    accessToken = null;
    ensureToken();
    response = httpClient.send(request, HttpResponse.BodyHandlers.ofString());
}
if (response.statusCode() != 200) {
    return Optional.empty();
}

Any other non-200 status is treated as "no deal for this route", not a crash.

04Prices in rupees

The search asks Amadeus for currencyCode=INR directly, so conversion is only a safety net. If an offer still comes back in another currency, CurrencyConverter applies a fixed, approximate rate and logs a warning, because a fare close to the threshold might then be misjudged. A wrong rate that says so beats a silent one.

CurrencyConverter.java
public double toInr(double amount, String currency) {
    if (currency == null || currency.isBlank() || "INR".equalsIgnoreCase(currency)) {
        return amount;
    }
    String code = currency.toUpperCase();
    double rate = approximateRateToInr(code);
    log.warn("Offer priced in {} instead of INR; converting at a fixed approximate rate of {}", code, rate);
    return amount * rate;
}

05Tests

The unit tests pin down the parts that decide whether a fare counts as a deal: currency conversion and configuration defaults.

CurrencyConverterTest.java
private final CurrencyConverter converter = new CurrencyConverter();

@Test
void convertsKnownCurrenciesAtFixedRates() {
    assertEquals(9000, converter.toInr(100, "EUR"), 0.01);
    assertEquals(8400, converter.toInr(100, "USD"), 0.01);
    assertEquals(10600, converter.toInr(100, "GBP"), 0.01);
}

@Test
void unknownCurrencyFallsBackToEurRate() {
    assertEquals(9000, converter.toInr(100, "CHF"), 0.01);
}

AppConfigTest checks that a minimal properties file falls back to the ₹20,000 threshold and the seven origin airports, with DEL first.

The testing idea

Test the decision, not the network. Whether ₹18,450 is a deal depends on conversion and threshold logic that runs offline, so those get unit tests. The HttpClient is passed in through the constructor, which leaves room to stub the API and cover the 401 and non-200 paths next.

06CI and the daily run

Two GitHub Actions workflows. CI builds and runs the test suite on every push and pull request to main, and uploads the Surefire reports even when a test fails. The scan workflow runs on a cron every morning, and can also be started by hand.

.github/workflows/daily-flight-scan.yml
on:
  schedule:
    - cron: '0 3 * * *'
  workflow_dispatch:
# ...
      - name: Run flight scan
        env:
          AMADEUS_KEY: ${{ secrets.AMADEUS_KEY }}
          AMADEUS_SECRET: ${{ secrets.AMADEUS_SECRET }}

Credentials live only in repository secrets. The workflow writes them into the properties file at run time, so they're never committed.
