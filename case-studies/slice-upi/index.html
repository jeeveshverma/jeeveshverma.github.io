01Context

At Slice I was an SDET-I, from August 2022 to May 2023. I led QA delivery for Slice UPI payments, a business-critical launch with a one-month deadline, during a critical business transition.

02The problem

Payments leave little room for error, and a one-month deadline leaves little room for slow manual regression. The work had to cover backend validation, regression and release readiness at the same time, without the regression cycle becoming the bottleneck.

03What I did

  1. Drove backend validation for the UPI launch.
  2. Integrated automated suites into CI/CD, so regression ran automatically instead of by hand.
  3. Identified and root-caused critical backend issues, including across the Rewards feature areas, improving defect detection before release.
  4. Ran performance and load tests for high-priority workflows, to surface scalability risks before production rollout.
  5. Owned release readiness for the launch.
The idea

Under a hard deadline, automating regression is not a luxury that competes with shipping. It is what frees up the time to test the risky parts properly.

04Results

MeasureOutcome
UPI payments launchQA delivered against a one-month deadline
Manual regression effortReduced by 90%
Defect detectionCritical backend issues found and root-caused before release
ScalabilityRisks surfaced through load testing before rollout

05What I'd take to the next team

  • Automate the repetitive regression first; it buys time for the risky, exploratory work.
  • Find the root cause, not just the symptom. A root-caused bug is fixed once.
  • Load-test before launch, not after. Scale problems are cheapest to find before customers do.
