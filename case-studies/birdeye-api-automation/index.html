01Context

At Birdeye I was an SDET working on backend and API flows, from May 2023 to June 2025. Two threads ran through the role: building the API automation practice, and leading QA for the Insight project.

02The problem

Backend changes need fast, repeatable validation. When API checks depend on manual runs, validation turnaround stretches out and release confidence depends on who ran what. The aim was automated coverage of backend and API flows that ran as part of the delivery pipeline, not beside it.

03What I did

  1. Built and scaled API automation with REST Assured and TestNG.
  2. Integrated the suite into Jenkins CI/CD, so validation runs as part of delivery.
  3. Led the Insight project end to end: defined the QA strategy, scaled the automation patterns, and improved release readiness for a business-critical initiative.
  4. Mentored junior engineers through code reviews, reusable patterns and test design best practices.
The idea

An automation practice is more than a suite. It is the patterns, reviews and habits that let other engineers add tests that are as good as the first ones.

04Results

MeasureOutcome
Automated coverage, backend/API flows98%

Insight projectQA strategy defined and delivered end to end

05What I'd take to the next team

  • Put the suite in the pipeline early. A suite outside CI is a suite people forget to run.
  • Reusable patterns and code review keep automation quality up as more people contribute.
  • On a business-critical project, QA strategy is a deliverable in its own right, decided up front.
