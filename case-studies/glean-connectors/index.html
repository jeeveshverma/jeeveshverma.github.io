30% → 98%_

Owning release quality for enterprise data connectors, and turning a mostly manual qualification into an automated regression the team could trust.

01Context

At Glean I was the SDET for backend data connectors, the integrations that pull content from tools a company already uses so it can be searched. I led QA for 5+ connectors, including Google Drive, Greenhouse, Notion, Tableau and Workday.

Owning a connector meant owning its release validation end to end:

  • Crawling, including incremental crawls
  • Indexing, and whether content is visible in search results
  • Authentication and permissions, including multi-user access
  • MCP (Model Context Protocol) related workflows

02The problem

When I started, only 30% of connector regression was automated. Everything else was checked by hand before a release, which made qualification slow and repetitive: the same search-visibility and indexing checks, run again for every connector, every release.

Manual checking also has a ceiling on what it catches. Many connector failures only show up under a particular feature flag, config or environment, and those combinations are exactly what a person running a checklist tends to miss.

03What I did

  1. Expanded regression automation across the connectors from 30% to 98%, so a release candidate is exercised the same way every time.
  2. Built reusable backend test workflows for connector and MCP-related releases, instead of a bespoke suite per connector. The repeated manual checks across search visibility and indexing became shared workflows.
  3. Debugged failures to root cause, not just reported them, across feature-flag, config and environment-specific failures.
  4. Treated release qualification as the deliverable: a clear signal on whether a backend rollout was safe to ship.
The idea

Connectors fail in combinations: this flag, that config, this environment. Automation only pays off when it covers those combinations reliably, release after release.

04Results

MeasureOutcome
Connector regression automation30% → 98%
Manual validation per releaseReduced by about one week
Launch-blocking issues found and debugged100+
Release qualificationFaster for connector and MCP-related releases

The 100+ issues were caught before launch, across feature-flag, config and environment-specific failures, which is what improved release confidence for backend rollouts.

05What I'd take to the next team

  • Coverage is a means. The goal is a release signal people believe; a suite that is 98% automated but flaky is worse than a smaller one that is trusted.
  • Build workflows, not one-off suites. The second connector should cost far less to cover than the first.
  • Test the environment, not just the code. Flags and config are part of the system under test.
