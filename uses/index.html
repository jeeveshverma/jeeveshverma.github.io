01Languages

  • Java for API suites: REST Assured, TestNG, JUnit and AssertJ.
  • Python for PyTest suites and quick scripts with Requests.
  • Go for side projects, using the standard library only. See linkforge and workq.

02Test automation

  • REST Assured + TestNG: my default for API regression in Java.
  • PyTest: fixtures and parametrisation for data-driven suites.
  • Cucumber when the people reading the tests aren't engineers.
  • Selenium for browser coverage.
  • JSON-driven test design: test data lives next to the test, not inside it.

03API & backend

  • Postman for exploring an API before I automate it.
  • curl for the quick check.
  • Integration, auth and permission-flow testing, plus crawl, indexing and search-result validation for search systems.

04Performance

  • JMeter for load and performance runs on high-priority flows.
  • go test -bench with -benchmem for my own code. Allocations are a number, not a feeling.

05CI/CD & infra

  • Jenkins and GitHub Actions to run suites on every change.
  • Docker and Kubernetes to test against something close to production.
  • Spinnaker for releases, and GCP services, including Secret Manager.
  • Git, always.

06Reporting

  • Allure reports, so a failure has a readable story.
  • CI results posted to Slack, so the team sees a red run before anyone asks.
Rule of thumb

A test report is for the person who didn't write the test. If they can't tell what broke from the report alone, the report is the bug.

07This site

Hand-written HTML, CSS and a little JavaScript, with no framework or build step. It's hosted on GitHub Pages, set in Inter and JetBrains Mono.
